# Events API

Учебный REST API для управления мероприятиями на ASP.NET Core Web API
и .NET 10. Проект первого спринта курса «Продвинутая разработка на C# и .NET».

## Требования

- .NET SDK 10.
- Git — для клонирования репозитория.
- Visual Studio необязательна: приложение можно запустить из терминала.

## Запуск

Клонируйте репозиторий и переключитесь на ветку первого спринта:

```sh
git clone https://github.com/BPS80/events-api.git
cd events-api
git switch sprint-1
```

Соберите и запустите приложение:

```sh
dotnet build
dotnet run
```

При запуске со стандартным профилем приложение доступно по адресу:

http://localhost:5095

Swagger UI для просмотра документации и выполнения запросов:

http://localhost:5095/swagger

Для остановки приложения в терминале нажмите Ctrl+C.

Также можно открыть EventsApi.slnx в Visual Studio
и запустить проект с профилем http.

## Хранение данных

Мероприятия хранятся в памяти приложения в List<Event>.
После остановки или перезапуска приложения данные теряются.

EventService зарегистрирован через DI как Singleton:
все запросы используют один экземпляр сервиса.

Доступ к списку защищён с помощью lock.
Сервис сохраняет и возвращает копии объектов, чтобы внешний код
не мог изменять хранилище в обход его методов.

## Модель мероприятия

| Поле | Тип | Описание |
|---|---|---|
| Id | Guid | Идентификатор, назначаемый сервером |
| Title | string | Обязательное название |
| Description | string? | Необязательное описание |
| StartAt | DateTime | Дата и время начала |
| EndAt | DateTime | Дата и время окончания |

## Эндпоинты

| Метод | Маршрут | Результат |
|---|---|---|
| GET | /events | 200 — список мероприятий, включая пустой список |
| GET | /events/{id} | 200 — мероприятие; 404 — не найдено |
| POST | /events | 201 — создано; 400 — некорректные данные |
| PUT | /events/{id} | 204 — обновлено; 400 — некорректные данные; 404 — не найдено |
| DELETE | /events/{id} | 204 — удалено; 404 — не найдено |

Параметр id должен иметь формат Guid.

POST возвращает созданное мероприятие и заголовок Location
со ссылкой на получение этого мероприятия по ID.

PUT полностью заменяет название, описание и даты.
Идентификатор сохраняется. Если описание не передано,
оно становится null. PUT не создаёт новое мероприятие
при отсутствии указанного ID.

Успешные PUT и DELETE возвращают ответ без тела.

## Пример запроса

Тело запроса для POST /events и PUT /events/{id}:

```json
{
  "title": "Практика ASP.NET Core",
  "description": "Проверка API через Swagger",
  "startAt": "2026-12-15T10:00:00Z",
  "endAt": "2026-12-15T12:00:00Z"
}
```

Даты передаются в формате ISO 8601.
В примере используется UTC — суффикс Z.
Для единообразия рекомендуется передавать даты в UTC.

Id не передаётся в теле запроса:
при создании его назначает сервер,
а при обновлении он берётся из маршрута.

## Валидация и ошибки

- Title обязателен и не может быть пустым или состоять из пробелов.
- StartAt и EndAt обязательны.
- EndAt должен быть строго позже StartAt.
- Description необязателен.
- Некорректный запрос возвращает 400 с описанием ошибок.
- Отсутствующее мероприятие возвращает 404.
- Ошибки контроллера возвращаются в формате ProblemDetails,
  ошибки валидации — ValidationProblemDetails.
- Некорректное обновление не изменяет сохранённое мероприятие.

## Структура проекта

- Controllers/EventsController.cs — маршруты, вызовы сервиса,
  преобразование DTO и HTTP-ответы.
- Models/Event.cs — модель мероприятия.
- DTOs/EventRequest.cs — входные данные и правила валидации.
- DTOs/EventResponse.cs — данные ответа API.
- Services/IEventService.cs — интерфейс сервиса.
- Services/EventService.cs — операции с мероприятиями и хранение в памяти.
- Program.cs — регистрация зависимостей, контроллеров и Swagger.
- Properties/launchSettings.json — профиль локального запуска.

## Ручная проверка

Через Swagger проверены:

- создание мероприятия: 201, новый Id и заголовок Location;
- получение списка и мероприятия по ID: 200;
- обновление: 204, изменения доступны при последующем GET;
- удаление: 204, последующий GET по ID возвращает 404;
- пустой список: 200 и [];
- GET, PUT и DELETE для отсутствующего мероприятия: 404;
- отсутствие обязательных полей: 400;
- название из пробелов: 400;
- окончание раньше начала или одновременно с ним: 400;
- некорректное обновление: 400, исходные данные сохраняются.
